# Story 7.1 · Month-end close agent

## TL;DR

| | |
|---|---|
| Goal | An LLM-driven agent that drafts the cited month-end commentary, triages store-level alerts and exceptions, and sends approved items to the right channel |
| How | Deep Agents supervisor + sub-agents in a container on AgentCore Runtime in our VPC; Claude on Bedrock (EU); data tools = Unity Catalog functions over MCP; channels = MCP tools behind AgentCore Gateway ([ADR-006](../conception/adr/ADR-006-agent-platform.md)) |
| Guardrails | Enforced outside the model: own read-only identity, no employee-level data, figure check, send tools refuse unapproved items |
| Hardest part | The account itself: Bedrock and AgentCore Runtime are held at zero by AWS's new-account verification; everything else is built and tested |

## Context

> **TL;DR:** the ML finds; the agents explain, draft and route; a person decides.

The controller spends days writing variance commentary for the CFO pack and emailing findings to
the right teams ([business case](../conception/business-case.md#todays-close-as-is)). Gold, the
reconciliation and the models already hold every fact needed.

## Design

> **TL;DR:** infra adds the runtime, gateway, identities and endpoints; the data repo adds the agent, its tools and its tables.

| Piece | Repo | What |
|---|---|---|
| Endpoints | infra | Bedrock runtime, AgentCore (data plane, gateway), ECR (api, dkr), CloudWatch Logs; 443 from a new agent SG |
| Agent identity (Databricks) | infra | Service principal `finance-month-end-agent`: EXECUTE on `finance.agent` functions, MODIFY on `ops.agent_drafts` and `ops.agent_runs`; group `finance-controllers` alone can write `ops.agent_approvals` |
| AgentCore Runtime | infra | Runtime attached to the private subnets; execution role: Bedrock EU ARNs, Gateway invoke, logs; image from ECR |
| AgentCore Gateway | infra | Targets: `publish_commentary`, `send_message` (stand-in channel, or Teams with a Microsoft 365 tenant), `open_case` (simulated); Identity holds their credentials; Policy allows only this agent |
| Data tools | data | Unity Catalog SQL functions in `finance.agent`: revenue vs budget, store margin alerts, reconciliation exceptions (no journal text), forecast, cashier case count; exposed over MCP |
| Agent | data | `create_deep_agent` supervisor; sub-agents: commentary writer, alert triage, distributor; model via LangChain Bedrock chat model; pinned versions; container built in CI |
| Tables | data | `ops.agent_drafts`, `ops.agent_runs` (traces, tokens, cost), `ops.agent_approvals`, `gold.close_commentary` (approved text for Power BI) |
| Check | data | Every number in a draft must equal a value returned by a tool; otherwise `rejected_by_check` |

## Acceptance criteria

- [ ] No public route: the runtime has no internet; flow logs show only endpoint traffic.
- [ ] Model calls only to the EU Claude profile (IAM simulator: other models refused).
- [ ] The agent identity can execute only `finance.agent` functions and write only its ops tables: refusals shown for Silver, `gold.fraud_scores`, a Gold write and a GRANT.
- [ ] No employee-level data reaches the model (test on every function).
- [ ] The agent refuses to run unless the latest Gold build is certified.
- [ ] The supervisor plans and delegates by itself (trace shows its plan and sub-agent calls); no fixed sequence in code.
- [ ] The August 2026 draft covers revenue vs budget, the four unsupported journals, the S031 margin alert, the number of cashier cases referred to internal audit, and the forecast; every figure cited and checked.
- [ ] A send before approval is refused by the gateway tool; after a controller approves, the next run delivers it to the stand-in channel and to `gold.close_commentary`.
- [ ] Traces, tokens and cost per run recorded.

## Out of scope

- Real Teams, ServiceNow and Power BI tenants (a stand-in channel behind the same gateway tool); an approval screen (approvals are rows in `ops.agent_approvals`).

## Tricky parts

> **TL;DR:** six surprises, each found by a live call, not by reading docs.

### 1. The account is not allowed to run models or agents yet
- **Symptom:** every Bedrock call returns "Operation not allowed" or "account is currently being verified"; the Anthropic first-use form says "open a support case"; creating the AgentCore runtime fails with "maxAgents limit exceeded".
- **Cause:** a new-account hold: the AgentCore quotas are pinned at 0 (default 1,000) and cannot be raised by a quota request.
- **Fix:** AWS Support case by the account owner. Everything around the model is built and tested without it (below).
- **Lesson:** check the account's AI quotas on day 0, before designing around a managed service.

### 2. Functions run with their owner's rights
- **Finding:** the notifier cannot `SELECT` `gold.fraud_scores`, yet `cashier_case_count` returns 4 of 235 for it, and the agent gets the same through MCP.
- **Consequence:** the six direct Gold table grants were unnecessary and are removed. The agent sees only what the functions return; the R-12 boundary is the review of `agent_tools.sql`.
- **Lesson:** test the permission model you rely on, then remove what it makes redundant.

### 3. Grants need account groups; SQL needs an entitlement
- The first apply failed: Unity Catalog could not find the workspace-level `finance-controllers` group (recreated at account level).
- The notifier's first SQL call got 403 until it had `databricks-sql-access`.

### 4. A bag-of-numbers check proves where a figure comes from, not what it means
- A correct draft was rejected for "80%" (the forecast range level, which no tool returned: now `range_pct`).
- An invented "EUR 3.45m" passed because it equals a real November forecast bound. The check guarantees every figure exists in the tools' output; that the figure is attached to the right label stays the controller's review.

### 5. Two Git clients, two line endings
- A branch switch across Windows Git and WSL Git committed CRLF copies of five files (content unchanged). LF is now enforced by `.gitattributes` in both repos.

### 6. The post-merge plan holds the state lock
- The first runtime deploy failed with HTTP 412 on the lock: the CI plan of the same commit was running. Rerun after CI (same lesson as [2.2](2.2-private-network.md)).

## Review

> **TL;DR:** two independent passes (infra, data) before merge; every high finding fixed or settled by a live test.

| Severity | Finding | Outcome |
|---|---|---|
| High | Deploy role missing permissions (Lambda concurrency, CreateSecurityGroup on the VPC) | Fixed (phase 1b); reserved concurrency dropped |
| High | Figure check let invented figures through (loose tolerance, x100 on everything, years and small numbers skipped) | Fixed: exact match after rounding or truncation, two significant digits, title checked |
| High | `cashier_case_count` would fail if functions used invoker rights | Tested live: owner's rights; direct grants removed |
| High | CI agent job would fail (pytest without its dependencies) | Fixed |
| High | Runtime would fail its health check (server bound to 127.0.0.1 in a microVM) | Fixed: `DOCKER_CONTAINER=1` |
| Medium | Agent deploy role could change the Databricks network | Fixed: changes only on `Component=agent` resources |
| Medium | `send_approved` could send twice | Fixed: claim the draft before sending, roll back on failure |
| Medium | CFO overview compared an incomplete month with a full one | Fixed: same days last year; variance on stores with a budget |
| Medium | Sub-agents have no step limit (cost) | Fixed: hard caps on submit and send per run |
| Low | Owner is both admin and controller | Accepted for the portfolio |

## Proof

- **Infra:** agent/ stack applied (26 resources: 7 endpoints, runtime SG, ECR, Gateway with IAM auth, Lambda target, SES identity, secrets); Databricks identities, controllers group, warehouse, tables; access audit 47 securables, 0 violations.
- **Tools:** six functions created by the runner; called as the agent through Databricks managed MCP: August 2026 net sales EUR 3,194,672.51 vs budget EUR 3,316,400.00 (-3.67%), +1.14% on the same days last year, margin 33.67%; S031 flagged #1 (margin 24.82% vs 31.75%, discount 14.48% vs 5.63%); 4 unsupported journals; 4 cashier cases referred.
- **Channel tools through the real Gateway (SigV4):** a CFO draft with correct figures is recorded `pending_review`; the same draft with an invented "EUR 3.27m" is `rejected_by_check` naming that figure; `send_approved` refuses an unknown or unapproved draft; the notifier's attempt to write an approval is refused (no MODIFY on `agent.approvals`).
- **Waiting on AWS:** Bedrock model access and AgentCore runtime quota (support case), then the first agent run; SES address verification (owner's inbox).
