## Context

> **TL;DR:** the console is fine for learning; enterprises need the same workspace every time.

A separate stack (D-022) keeps the blast radius small: the Databricks credentials never
touch the AWS foundation. It reads bootstrap outputs through remote state, never the reverse.

## What we built

> **TL;DR:** Terraform tells Databricks where our VPC, roles and buckets are, then asks for a workspace.

| Registration | Tells Databricks |
|---|---|
| Credentials | Which IAM role to assume to launch EC2 (cross-account role) |
| Storage configuration | Which bucket is the workspace root (`dbx-root`) |
| VPC endpoints ×2 | Our PrivateLink endpoints (workspace, relay) |
| Private access settings | Back-end traffic must use PrivateLink |
| Network | Our VPC, subnets, SG |

Auth: service principal `terraform-platform`, OAuth machine-to-machine, secret in GitHub
secrets and `~/.databrickscfg` locally (never in Git, never printed).

## Tricky parts

> **TL;DR:** five Terraform lessons in one day.

### 1. "Unable to load OAuth Config"
- **Cause:** `databricks_mws_vpc_endpoint` needs `account_id`; the provider does not mark it required.
- **Fix:** pass `account_id` on every `mws_*` resource.
- **Lesson:** when an error blames auth but other resources authenticate fine, suspect the resource.

### 2. IAM is eventually consistent
- **Cause:** a freshly created role is not visible to Databricks for a few seconds.
- **Fix:** `time_sleep` between the role policy and its first use.

### 3. Null outputs vanish
- **Cause:** Terraform does not store outputs whose value is null; the other stack then
  fails with "Unsupported attribute" instead of a readable message.
- **Fix:** read them with `try(..., null)` and let a `precondition` explain.

### 4. Sensitive values cannot drive `count`
- **Fix:** `nonsensitive(var.workspace_admin_user != null)`: only *whether* it is set leaks, not the value.

### 5. The cross-account role is "restricted"
- Its policy is pinned to our VPC and SG, and its trust to our Databricks account via external ID.
