## Context

> **TL;DR:** the usual way to blow a Databricks budget is one forgotten large cluster.

## What we built

> **TL;DR:** small by default, private by default, loud when spend grows.

| Guardrail | Setting |
|---|---|
| `finance-small` (interactive) | m6gd/m5d large or xlarge, 0-2 workers, spot + on-demand driver, no Photon, auto-stop 10-30 min |
| `finance-jobs` (job clusters) | Same limits, no auto-stop (job clusters stop when the job ends) |
| Serverless network policy | Egress restricted to `dbx-uc` only |
| Databricks budget | Alerts at USD 100 / 200 / 300 / 380 |
| Users group | No cluster creation, asserted on every plan |

## Tricky parts

> **TL;DR:** read-only API calls found what the docs did not say.

### 1. Network policy ID: 32 characters max
- **Symptom:** "Invalid NetworkPolicyId" on a 45-character ID.
- **Cause:** undocumented limit. Found with read-only GETs, not guesses.
- **Fix:** `retail-finance-serverless` + a `precondition` so the next person gets a clear message.

### 2. The budget that always changes
- **Cause:** the API rewrites `100` as `100.000000000000000000`, reorders alerts, adds an empty filter.
- **Fix:** `ignore_changes` on those fields; thresholds verified via API.

### 3. Locked entitlements
- **Cause:** new workspaces lock the `users` group entitlements; Terraform cannot set them.
- **Fix:** they are already empty, so the resource became a `check` block that fails the plan if that changes.

### 4. One policy cannot serve both cluster kinds (2026-09-26)
- **Symptom:** the first job was rejected twice ([3.3](3.3-first-job-in-the-private-vpc.md)).
- **Causes:** autoscale was mandatory (missing `isOptional`); a fixed `CostCenter` tag clashed
  with the workspace tag; job clusters do not support auto-stop.
- **Fix:** split into `finance-small` and `finance-jobs` sharing one `common_policy` block.

### 5. Teardown order
- Deleting the network policy assignment is a no-op, so the workspace `depends_on` the policy
  to make destroy run in the right order.
