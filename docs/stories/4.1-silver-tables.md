## Context

> **TL;DR:** Bronze is the unopened delivery; Silver is unpacked and checked.

Bronze keeps everything as text so nothing is lost at load time. Silver is where types,
keys and rules are enforced. See [STATUS · Bronze, Silver, Gold](../../STATUS.md#bronze-silver-gold).

## Acceptance criteria

> **TL;DR:** nothing lost, nothing duplicated, nothing silently fixed.

- [ ] Dates are `DATE`/`TIMESTAMP`, amounts `DECIMAL(18,2)`, quantities integers.
- [ ] One row per business key (e.g. receipt + line); duplicates removed, count logged.
- [ ] Rows that fail a rule go to `silver.quarantine` with source, key and reason.
- [ ] Bronze rows = Silver rows + quarantined rows + removed duplicates, per source.
- [ ] Amounts keep their currency and gain an EUR column using the ECB rate of the day.
- [ ] Re-running the job adds nothing (idempotent).
- [ ] Tests in CI for each rule; the job runs under `finance-jobs` as the service principal.

## Design notes

> **TL;DR:** decide at start between plain PySpark tasks and Lakeflow declarative pipelines.

| Option | For | Against |
|---|---|---|
| PySpark tasks in the existing bundle | Same pattern as Bronze, already proven in the private VPC | Quality rules hand-written |
| Lakeflow declarative pipelines (expectations) | Built-in data quality metrics and lineage | New moving part; check it runs on classic compute in our VPC |
