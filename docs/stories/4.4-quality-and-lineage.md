## Context

> **TL;DR:** "trust me" is not evidence; a failed check and a traceable number are.

Silver already enforces row rules (story [4.1](4.1-silver-tables.md)). What a single row cannot
show: a journal that no longer balances, a file that never arrived, Silver changing while Gold
is being built, or where a Gold number came from.

## How it works

> **TL;DR:** check Silver, build, check Gold, certify, trace.

`build_gold` runs: `quality_silver` → `reconcile_gl_pos` → `finance_tables` → `quality_gold`,
both gates carrying the Databricks run id.

| Check | Severity | Catches |
|---|---|---|
| `journals_balance` | Critical | A ledger journal whose debits no longer equal its credits |
| `amounts_in_range` | Critical | Absurd sales, refund or ledger amounts (EUR) |
| `quarantine_money` | Critical | Money rows set aside in Silver (Gold would be understated) |
| `silver_keys_unique`, `sales_have_masters` | Critical | Tripwires for a regression in the Silver code |
| `gold_adds_up`, `silver_unchanged` | Critical | Gold not matching Silver; Silver rewritten during the run |
| `missing_store_days` | Warning | An open day (holiday calendar) with no sales: a missing file |
| `volume_collapse`, `row_count_drop` | Warning | A day under a third of usual volume; a table losing >5% of rows |
| `refund_within_sale`, `quarantine_masters`, `lineage_traced` | Warning | Refund above its sale; master rows set aside; lineage gaps |

Outputs: `ops.dq_results` (every result), `ops.silver_snapshot` (versions and counts approved),
`ops.gold_certification` (certified yes/no per run: ML and the agent use Gold only from certified
runs), `ops.lineage_evidence` (table chains and one number traced to its files).

## Tricky parts

> **TL;DR:** the review rewrote the lineage design; the data caught a false alarm in a new check.

### 1. The independent review

| Severity | Finding | Outcome |
|---|---|---|
| High | Lineage "proof" read a system table we had no grant on (silent warning), used stale links from any run, and picked an arbitrary "sample file" | Fixed: lineage REST API filtered to this job, plus a real row trace (one Gold number → its Silver and Bronze rows → its files) |
| Medium | Silver could be rewritten by the Silver job between the gate and the Gold build | Fixed: Delta versions recorded at the first gate, compared at the last |
| Medium | The Gold gate failed only after Gold was visible, with nothing marking it untrusted | Fixed: `ops.gold_certification` per run |
| Medium | Quarantined refunds or budget rows would silently understate Gold | Fixed: critical for all money tables |
| Medium | Missing checks: missing file, refund above sale, row-count drop | Fixed; freshness accepted (static dataset until stage 6) |
| Medium | Two checks duplicate Silver guards | Kept, labelled as regression tripwires |
| Low | Results not tied to a job run; one table missing from the lineage list | Fixed: `{{job.run_id}}`, list completed |
| Low | The broken-file test is not an Auto Loader run on the workspace | Accepted: Bronze is append-only, an edited file would stay forever; the test feeds CSV-shaped rows through the real Silver code |

### 2. A new check fired on clean data
- `refund_within_sale` flagged 3 refunds on data that is clean by construction. A Swiss refund is
  converted at the refund day's rate, the sale at the sale day's rate: in EUR the refund can exceed
  the sale by cents. The check now compares in the till's own currency.
- **Lesson:** compare money in the currency it was transacted in; FX belongs to reporting.

### 3. Lineage for the finance tables (open, R-11)
- Unity Catalog lineage shows Bronze → Silver and Silver → reconciliation tables, each tagged with
  the job that wrote it. The 4 finance tables show none, over four runs.
- Tested: recording lag (none after hours); writing from cached DataFrames (fixed in PR #17, still
  none right after the run). Not yet explained. The audit trail is covered by the reconciliation
  lineage and the row trace; re-check before stage 4 closes.

## Acceptance criteria

- [x] Critical checks fail the job: keys, amounts, references, balanced journals, Gold vs Silver
- [x] Warning checks write to `ops.dq_results` without failing (volume, missing days, refunds)
- [x] A deliberately broken file fails the run with a readable message (test: one edited ledger line → `journals_balance: 1 (… J…)`)
- [~] Lineage from Gold back to Bronze `_source_file`: reconciliation tables and a row trace, yes; finance tables pending (R-11)
- [x] Control matrix data-quality and lineage rows can move to Implemented, evidence "tested"

## Review

- [x] Evidence: workspace run results and 11 named tests
- [x] Break it: unbalanced journal, duplicate keys, absurd amounts, quarantined money rows, a missing file, a collapsed day, an inflated refund, Silver changed mid-run
- [x] Security: no new grants, no secrets; lineage read through the workspace API as the service principal
- [x] Cost: two extra tasks on the same job cluster, minutes per run
- [x] Data: nothing certified unless every critical check passed on the Silver versions actually used
- [x] Failure: results recorded before the job fails; rerun appends, certification per run
- [x] Docs: story, cmdb (R-11), STATUS updated
- [x] Simplicity: tripwires kept on purpose, labelled
