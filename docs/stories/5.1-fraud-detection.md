## TL;DR

| | |
|---|---|
| Goal | Rank cashiers and stores by how unusual their refunds and margins are, every month |
| Models | Two unsupervised detectors (Isolation Forest): cashier refunds, store margin drift |
| Honesty rule | Trained **without** the answer key; the planted anomalies are used only to score the result |
| Output | `gold.fraud_scores`, `gold.margin_alerts`; models in MLflow, registered in `finance.ml` |
| Runs on | Our job cluster, as `finance-pipeline-runner`, from certified Gold only |

## Context

> **TL;DR:** Gold already shows the frauds to someone who knows where to look; a model must find them without being told.

Story [4.3](4.3-gold-finance-tables.md) ranked S031 and S017-C03 first with hand-written queries.
A detector generalises that: it scores every cashier and store every month, so a new pattern
surfaces without anyone writing a new query.

## Acceptance criteria

> **TL;DR:** find A1 and A2 near the top, few false alarms, fully tracked.

- [ ] Reads only Gold tables, and only when the latest `ops.gold_certification` row is certified.
- [ ] Cashier detector: S017-C03 is in the top 3 cashier-months for August and September 2026.
- [ ] Margin detector: S031 is in the top 3 store-months for each of July, August, September 2026.
- [ ] False alarms reported: flags that are not planted anomalies, per month.
- [ ] No answer-key column is a model feature (checked by a test).
- [ ] Parameters, metrics and models logged to MLflow; models registered in Unity Catalog `finance.ml`.
- [ ] Scores written to `gold.fraud_scores` and `gold.margin_alerts`, readable by analysts.

## Design notes

- Features are ratios to the store's own peers (cashiers of the same store, the store's own past),
  so a big store does not look suspicious just for being big.
- Isolation Forest: no labels, robust on a few thousand rows, explainable enough with the features
  shown next to each score.
