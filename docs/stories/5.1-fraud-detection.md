## TL;DR

| | |
|---|---|
| Goal | Rank cashiers and stores by how unusual their refunds and margins are, every month |
| Models | Two unsupervised detectors (Isolation Forest): cashier refunds, store margin drift |
| Honesty rule | Trained **without** the answer key; the planted anomalies are used only to score the result |
| Output | `gold.fraud_scores`, `gold.margin_alerts`; models in MLflow, registered in `finance.ml` |
| Runs on | Our job cluster, as `finance-pipeline-runner`, from certified Gold only |

## Context

> **TL;DR:** Gold already shows the frauds to someone who knows where to look; a model must find them without being told.

Story [4.3](4.3-gold-finance-tables.md) ranked S031 and S017-C03 first with hand-written queries.
A detector generalises that: it scores every cashier and store every month, so a new pattern
surfaces without anyone writing a new query.

## Acceptance criteria

> **TL;DR:** find A1 and A2 near the top, few false alarms, fully tracked.

- [x] Reads only Gold tables, and only when the latest `ops.gold_certification` row is certified.
- [x] Cashier detector: S017-C03 is in the top 3 cashier-months for August and September 2026.
- [x] Margin detector: S031 is in the top 3 store-months for each of July, August, September 2026.
- [x] False alarms reported: flags that are not planted anomalies, per month.
- [x] No answer-key column is a model feature (checked by a test).
- [x] Parameters, metrics and models logged to MLflow; models registered in Unity Catalog `finance.ml`.
- [x] Scores written to `gold.fraud_scores` and `gold.margin_alerts`, readable by analysts.

## Design notes

- Features are ratios to the store's own peers (cashiers of the same store, the store's own past),
  so a big store does not look suspicious just for being big.
- Isolation Forest: no labels, robust on a few thousand rows, explainable enough with the features
  shown next to each score.

## Out of scope

- Real-time scoring and alerts (stage 6); case management.

## Review

> **TL;DR:** independent review before merge (fresh agent, story + diff): 3 high, 5 medium, all fixed or accepted.

| Severity | Finding | Outcome |
|---|---|---|
| High | False alarms not reported per month (acceptance criterion) | Fixed: per-month counts, logged to MLflow |
| High | UC registration would fail without a signature, after scores were already written | Fixed: signature + input example; all logging before any write |
| Medium | Production job would fail without an answer key | Fixed: evaluation optional |
| Medium | The 6-month rolling baseline absorbs a slow creep | Fixed: baseline = the store's own months 4-12 back |
| Medium | Partial writes; no provenance on scores | Fixed: writes last, `gold_run` + `scored_at` on every row |
| Medium | Employee-level fraud score readable by every analyst (GDPR, works council) | Accepted as R-12: pseudonymous IDs, synthetic data; production would restrict to internal audit |
| Low | Unstable ranks on ties, weak answer-key test | Fixed: raw-score ranks with key tie-break; test that the model input is exactly its features |

- [x] Evidence: workspace run numbers below and 6 named tests
- [x] Break it: answer-key column present in the frame; chain-wide promotion; reruns
- [x] Security: runner only; models in `finance.ml` (analysts no access); R-12 recorded
- [x] Cost: one single-node job run
- [x] Data: certified Gold only; writes after logging
- [x] Failure: a failure before the writes leaves Gold untouched; reruns rank identically
- [x] Docs: story, cmdb (R-12), STATUS, LLD 3
- [x] Simplicity: one model family for both detectors
