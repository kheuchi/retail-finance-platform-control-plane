# Story 6.1 · One scheduled pipeline

**Contents:** [TL;DR](#tldr) · [Context](#context) · [Design](#design) · [Acceptance criteria](#acceptance-criteria) · [Review](#review) · [Proof](#proof) · [References](#references)

Planned · Epic 6 · 2026-10-01 · Data repo · 🔄 In progress

## TL;DR

| | |
|---|---|
| Goal | The whole chain runs as one job, on a schedule, and tells someone when it fails |
| Built | Job `finance_pipeline`: Bronze → Silver → Gold → ML, queueing, failure email, schedule in Git |
| Schedule | Daily 06:00 Europe/Berlin, **committed paused** (owner decision: no daily spend before teardown); unpaused once for proof |
| Hardest part | The first real run: the runner was allowed to *be* each job's identity but not to *start* the jobs |

## Context

> **TL;DR:** four jobs started by hand are a demo; one scheduled job with alerts is operations.

Until now each job was started from the deploy workflow. Nobody would notice a failure, and the
order (Gold only after Silver, ML only after certified Gold) lived in our heads.

## Design

> **TL;DR:** a thin orchestrator over the existing jobs; no task is defined twice.

| Choice | Why |
|---|---|
| `run_job` tasks calling the existing jobs | Each job keeps its own cluster size and run history; nothing duplicated |
| New `ingest_bronze` job (load only) | The pipeline must not regenerate the data; Auto Loader loads only new files, so a run with no new file adds nothing |
| No automatic retries | A retry reruns a whole child job (new cluster, all tasks), and most failures here are deterministic (a quality gate). A failure alerts; "repair run" reruns only the failed step |
| Queueing on every job | A run that finds a job busy (e.g. a manual run) waits instead of being skipped |
| One owner per Auto Loader checkpoint | `generate_and_ingest` now calls `ingest_bronze` instead of running its own copy of the load |
| ML checks Gold was not rewritten after certification | A manual Gold run between the pipeline's Gold and ML steps would otherwise be scored as certified |
| Failure email to the alert address | Address kept out of Git (GitHub secret → bundle variable) |
| Schedule `pause_status` as a variable, default `PAUSED` | Owner decision; flipping it is one deploy, and a manual unpause is exactly what [6.2](6.2-drift-checks.md) should catch |

Cost: four job clusters start in sequence (~8 min each), roughly USD 1 per full run.

## Acceptance criteria

- [ ] `finance_pipeline` runs Bronze → Silver → Gold → ML in that order; a failed step stops the rest.
- [ ] No blind retries (amended after review); queueing on; overall timeout above the steps' own timeouts.
- [ ] A failed or cancelled run sends an email to the alert address; the address is not in Git.
- [ ] The schedule is defined in the bundle and deployed paused.
- [ ] Proof: one run started by the schedule completes; the ML scores' `gold_run` is the Gold run this pipeline certified.
- [ ] The schedule is paused again after the proof (redeploy with `PAUSED`).
- [ ] Proof: a cancelled run sends the email.

## Tricky parts

> **TL;DR:** the first run failed in a place no test or review could see.

### 1. Running as an identity is not permission to start the job
- **Symptom:** the first pipeline run failed at once: `PERMISSION_DENIED: User 11af38fd… ` on the Bronze step; the other three steps were skipped (as designed).
- **Cause:** the pipeline runs as `finance-pipeline-runner`, so it is the runner that starts the child jobs. Every child already runs as the runner, but until now only the deployer started them, so the runner had no right to (story 4.5 never needed it).
- **Fix:** `CAN_MANAGE_RUN` for the runner on the four child jobs (data PR #22). No escalation: it can start and cancel runs that already run as itself.
- **Lesson:** an orchestrator needs rights on what it orchestrates; only a real run shows the gap.

## Review

> **TL;DR:** independent pass (fresh agent, story + diff) before merge: 6 medium, 7 low.

| Severity | Finding | Outcome |
|---|---|---|
| Medium | Two jobs ran Auto Loader on the same checkpoint; overlapping runs could collide | Fixed: one owner (`ingest_bronze`), called by `generate_and_ingest` |
| Medium | A busy child job skips the triggered run: false failure and alert | Fixed: queueing on all jobs |
| Medium | ML trusted the newest certification row even if a later Gold build was rewriting the tables | Fixed: refuses if any Gold input was written after the certification (test) |
| Medium | Retrying a whole child job on a deterministic failure wastes up to hours of compute | Fixed: no blind retries; alert + repair run |
| Medium | No freshness check: an unchanged day still rebuilds everything | Accepted: the dataset is static in this project. Production answer: a file-arrival trigger on the landing volume instead of a clock |
| Medium | A missing alert secret would deploy an empty address | Fixed: workflows fail if it is empty |
| Low | Parent timeout below the children's sum; deploy workflow shorter than the pipeline | Fixed: 5 h timeout; pipeline started with `--no-wait` |
| Low | Cancelled-run email only implied | Fixed: `no_alert_for_canceled_runs: false` explicit; proven by test |
| Low | Proof did not tie ML scores to the pipeline's Gold run; re-pause not a step | Fixed: both are criteria |
| Low | Experiment `description` removed without a reason | Unsupported field (validate warning); noted in the PR |
