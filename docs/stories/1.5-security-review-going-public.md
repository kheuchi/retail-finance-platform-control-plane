## Context

> **TL;DR:** a private repo on the free plan cannot enforce branch protection.

So anyone with the account could push straight to `main`, and `main` is what the AWS
deploy role trusts (finding F-2). Making the repo public made protection free.

## Tricky parts

> **TL;DR:** secrets hide in history, and rewriting history has side effects.

### 1. Employer identity in commits
- **Cause:** Windows Git and WSL Git had different `user.email`; whichever shell committed decided the author.
- **Fix:** rewrote both histories to one personal identity; aligned all four Git configs.

### 2. Scan history, not just files
- Before publishing, the full history held the AWS account ID (4 commits) and an employer
  name (21 commits). Scrubbed by rewrite. Still visible: the account ID in Actions logs
  (accepted, D-016: an ID is not a credential).

### 3. The orphaned tags (my mistake)
- **Symptom:** two days later, semantic-release failed.
- **Cause:** the rewrite re-pointed the 3 tags in the local clone; 10 more existed only on the remote.
- **Fix:** remapped every tag to its rewritten commit by subject and date; v1.8.0 then cut cleanly.
- **Lesson:** verify against the remote, not a local clone.

## Proof

- `main` history under one identity; neither string on any live ref (verified).
- Push to `main` refused, even as admin.
