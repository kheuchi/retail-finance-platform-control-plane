# Story 5.2 · Revenue forecast

**Contents:** [TL;DR](#tldr) · [Context](#context) · [Acceptance criteria](#acceptance-criteria) · [Design notes](#design-notes) · [Out of scope](#out-of-scope) · [Review](#review) · [Proof](#proof) · [References](#references)

As-built · Epic 5 ML Models · 2026-09-29 · Repo: data-products · ✅ Done (the baseline ships)

## TL;DR

| | |
|---|---|
| Goal | Forecast each store's net sales for the next 3 months, with a range, for the month-end close |
| Model | Gradient boosting on seasonal and lag features, **against a seasonal-naive baseline** |
| Honesty rule | Shipped only if it beats the baseline in a backtest; otherwise the baseline ships |
| Output | `gold.revenue_forecast`; model in MLflow, registered in `finance.ml` |

## Context

> **TL;DR:** finance needs "where will we land this month and next", not a perfect model.

With 21 months of history, a year-over-year baseline is strong. A model is worth shipping only
if it measurably does better; that comparison is the deliverable.

## Acceptance criteria

- [x] Reads certified Gold only (`gold.daily_revenue`, `gold.budget_variance`).
- [x] Backtest on the last 3 complete months (trained on data before them): MAPE for model and baseline, per month.
- [x] The better of the two produces `gold.revenue_forecast` for the next 3 months, per store, with an 80% range from backtest errors.
- [x] The partial current month is forecast as a full month (useful for month-end), never trained on as if complete.
- [x] Parameters and backtest metrics logged to MLflow; the model is registered in `finance.ml` when it wins (amended: the baseline is a formula, nothing to register)

## Design notes

- Baseline: same month last year × recent year-over-year growth (last 3 months vs the same months a year earlier).
- Model features: month of year, horizon, store level, lags (1, 2, 12 months). The growth ratio was dropped after review: it needs 14 months of history and starved training.

## Out of scope

- Daily forecasts, promotions planning, cash forecast (stage 6+).

## Review

> **TL;DR:** the reviewer found the first backtest was rigged against the model by accident.

| Severity | Finding | Outcome |
|---|---|---|
| High | The model trained on 3 month-pairs with no horizon-3 example: "baseline wins" was decided before the comparison | Fixed: training from month 13, 200 rows per horizon; the baseline still wins, now fairly |
| High | Registering the model would fail (no signature) | Fixed; registered only when the model wins (criterion amended: the baseline is a formula) |
| Low | One range for all horizons; NaN-sensitive; per-month error not logged | Fixed: range per horizon, NaN-safe, per-month MAPE in MLflow |

- [x] Evidence: backtest metrics per month in MLflow and below
- [x] Break it: missing history (NaN), the partial month
- [x] Security, cost, failure, docs, simplicity: as 5.1

## Proof

Backtest (cutoff 2026-05, forecasting Jun-Aug; 200 training rows per horizon):

| Month | Model MAPE | Baseline MAPE |
|---|---|---|
| 2026-06 | 12.2% | 8.8% |
| 2026-07 | 11.5% | 6.8% |
| 2026-08 | 7.5% | 6.9% |

**Baseline ships.** Forecast (sum of stores): Sep EUR 3.43m (80%: 3.39-4.12m), Oct 3.65m, Nov 3.86m.
Sanity: September actual to the 25th, pro-rated to 30 days, is EUR 3.41m.

**Why the baseline wins:** with 21 months of history, last year's same month times recent
growth already captures seasonality and trend; the model has little more to learn. It becomes
worth revisiting with more history or extra signals (promotions, holidays).
