## Tricky parts

> **TL;DR:** stop guessing, read the flow logs.

### 1. Run 3 looked like a permissions problem
- The file existed and the principal owned it. We moved to a volume (S3 through the gateway
  endpoint, a path already proven). That was a sensible workaround, not the root cause.

### 2. Run 4 proved it was not about files
- "Connection reset" from a volume too meant the problem was on the network path to the
  **control plane**, which brokers both downloads.

### 3. The flow logs named the port
- Query on the audit bucket's flow logs: more than 1,000 **REJECT** records from cluster IPs
  to the workspace endpoint on ports **8443-8449**.
- Our endpoint SG admitted only 443 and 6666. The workspace SG already allowed 8443-8451
  *outbound*, so the rule was missing on one side only.
- **Fix:** endpoint SG ingress 8443-8451 from the workspace SG. One rule.
- **Lesson:** security groups must match on **both** ends; flow logs show which end drops.
