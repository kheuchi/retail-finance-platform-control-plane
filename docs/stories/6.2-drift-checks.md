# Story 6.2 · Drift checks

Planned · Epic 6 · 2026-10-01 · Data repo · 🔄 In progress

## TL;DR

| | |
|---|---|
| Goal | Know when the data under a model shifts, and when a deployed job no longer matches Git |
| Model drift | PSI per feature, each complete month vs the model's reference months → `ops.model_drift` + MLflow |
| Config drift | Nightly GitHub workflow runs `bundle plan`; any pending change = someone edited the workspace by hand |
| Both are warnings | Drift is a signal to look, not a reason to stop the pipeline |
| Hardest part | Making PSI honest on small and mostly-zero populations |

## Context

> **TL;DR:** "drift" means two different things; both are blind spots today.

| Kind | Question | Today |
|---|---|---|
| Model (data) drift | Does this month's data still look like what the model was built on? | Not measured |
| Config drift | Is the deployed job still what Git says? | Push deploy: a manual edit in the UI stays until the next deploy |

## Design

> **TL;DR:** PSI for populations, `bundle plan` for configuration.

**PSI (population stability index):** split the reference months into bins by quantile, count
the share of the current month in each bin, sum `(cur − ref) × ln(cur / ref)`. Rule of thumb:
< 0.1 stable, 0.1-0.2 watch, > 0.2 drift. About 10 current rows per bin (2 to 10 bins), and the
reference minimum keeps its own bin (see tricky parts).

| Model | Features checked | Reference |
|---|---|---|
| Cashier refunds | its 5 features | The months 4-12 before the month checked (same gap as the margin baseline) |
| Store margin | its 2 features | Same |
| Forecast | year-over-year growth per store (raw sales would "drift" every December) | Same; needs a year of history, so from 2026-07 |

**Honest limit, stated up front:** PSI measures a shift of the *whole population*. One cashier or
one store out of 40 (the planted frauds) barely moves it; catching those is the detectors' job.
PSI catches a chain-wide change: a new promotion policy, a pipeline bug that halves refunds,
a currency problem.

**Config drift:** `databricks bundle plan -o json` as the deployer, nightly and on demand. Any
create, update or delete on main's configuration fails the workflow (the email comes from GitHub).

## Acceptance criteria

- [ ] PSI per feature for the last 6 complete months of each model, in `ops.model_drift` (model, feature, month, psi, status, gold_run) and as MLflow metrics.
- [ ] Unit tests: same distribution → stable; shifted distribution → drift; constant reference → no crash.
- [ ] Drift never fails the ML job; it prints a summary.
- [ ] The drift workflow passes when the workspace matches main (the plan's actions are printed as evidence).
- [ ] Proof: a manual change in the workspace that differs from main fails the workflow; a deploy clears it. (Amended after review: main temporarily says `UNPAUSED` for 6.1, so unpausing by hand would not differ from main.)

## Tricky parts

> **TL;DR:** PSI is easy to compute and easy to fool.

### 1. Few rows: noise reads as drift
- **Symptom:** a test with 50 rows a month, identical distributions, read "watch".
- **Cause:** with 10 bins, sampling noise alone gives about (bins − 1) / rows. 40 stores in 10 bins read ~0.2: "drift" every month on the margin detector.
- **Fix:** about 10 rows per bin (40 stores → 4 bins); a test checks the median PSI on identical data stays under 0.1.

### 2. Mostly zeros: drift reads as nothing (found by the review)
- **Cause:** if over 90% of a feature is 0 (no-receipt refunds), every quantile edge is 0; everything fell into one bin and PSI read 0 whatever happened.
- **Fix:** the reference minimum keeps its own bin. Test: 92% zeros vs all non-zero → drift.

### 3. A hand edit changes more than you typed
- The proof edit (`jobs update`, timeout 3500 on `ingest_bronze`) did not set the job timeout at all: it set the **task** timeout and flipped the job from `UI_LOCKED` to `EDITABLE`. Bundle-deployed jobs are locked in the UI; an admin edit unlocks them.
- `bundle plan` saw the change (it compares with the live workspace, not only its own state), and the next deploy restored both fields.

### 4. Clean data already shows drift, and it is real
- Local probe on the full data: revenue YoY growth reads **0.57 in August 2026**. Growth fell chain-wide (about 2% vs 6-8% earlier) because of the calendar: August 2026 swaps five Fridays for five Mondays; Ascension and Whit Monday move between May and June.
- That is what PSI is for, and it exposes a blind spot of the shipped baseline forecast: it ignores trading days.
- Margin features (40 stores) read 0.45 in March and 0.40 in June: small populations stay fragile even with fewer bins. Treated as "look", not "act".

## Review

> **TL;DR:** independent pass (fresh agent, story + diff) before merge: 3 high, 4 medium, 6 low.

| Severity | Finding | Outcome |
|---|---|---|
| High | Mostly-zero features always read PSI 0 | Fixed: the minimum keeps its own bin; test |
| High | Proof by unpausing cannot fail while main says UNPAUSED | Fixed: criterion amended (any manual change that differs from main) |
| High | Unsure whether `bundle plan` sees edits made in the workspace at all | Confirmed it does: proof below |
| Medium | "Drift never fails the job" was not enforced | Fixed: compute and write wrapped; warning printed |
| Medium | "Unchanged" action word guessed | Fixed: case-insensitive; actions printed per run as evidence |
| Medium | Wheel rebuild might show as a change every night | Settled: a clean run plans `skip` for all 12 resources |
| Medium | Sharing the deploy concurrency group could replace a pending deploy | Fixed: own group |
| Low | Reference window counted list positions, not calendar months | Fixed: calendar months; test with a gap |
| Low | "no reference" also hid all-missing data | Fixed: separate `no data`; window length recorded |
| Low | Reruns append duplicate rows | Accepted: read the latest `scored_at` per `gold_run` |
| Low | No alert-email guard in the drift workflow | Fixed |
| Low | Ties give uneven bins; EPS not renormalised | Accepted: same on both sides, negligible |
| Low | Story out of date (bins, forecast input, limits) | Fixed (this page) |
