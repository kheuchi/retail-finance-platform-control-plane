# Story 4.5 · Split the service principal

**Contents:** [TL;DR](#tldr) · [Context](#context) · [Target identities](#target-identities) · [Acceptance criteria](#acceptance-criteria) · [Plan](#plan) · [Out of scope](#out-of-scope) · [References](#references)

Planned · Epic 4 (after [4.3 Gold](4.3-gold-finance-tables.md)) · Repos: infra, data-products · Planned

## TL;DR

| | |
|---|---|
| Problem | One service principal, `terraform-platform`, is account admin **and** deploys the bundle **and** runs the data jobs |
| Risk | A bug or compromise in data code runs with account-admin power |
| Target | Three identities: platform (Terraform), deployer (bundle CI), runner (jobs) |
| When | After Gold, so identities don't change mid-pipeline build |
| Risk ID | R-10 in [`cmdb.yml`](../../cmdb.yml) |

## Context

> **TL;DR:** it works today because one identity can do everything. That is the problem.

`terraform-platform` was created on day one for Terraform ([2.3](2.3-workspace-as-code.md)).
The data repo reused it ([3.2](3.2-catalog-and-bundle-deploy.md)), so the job page shows
"Run as terraform-platform". Least privilege says each duty gets its own identity with only
the grants that duty needs.

## Target identities

> **TL;DR:** each identity can do one job and nothing else.

| Identity | Used by | Can | Cannot |
|---|---|---|---|
| `terraform-platform` (keep) | Infra CI only | Account admin: workspace, network, catalog, grants | Be used by the data repo |
| `finance-data-deployer` (new) | Data repo CI | Deploy the bundle to its own folder, create/update its jobs, upload to `ops.artifacts` | Change grants, create clusters outside policy, run as itself |
| `finance-pipeline-runner` (new) | Jobs ("Run as") | Read/write `finance` schemas and volumes, use `finance-jobs` policy | Admin anything, change grants, read other catalogs |

## Acceptance criteria

> **TL;DR:** prove each identity is limited by trying what it must not do.

- [ ] Both new service principals, their grants and policy permissions are managed in Terraform (infra repo).
- [ ] The deployer has the "Service Principal User" role on the runner only, so it can set `run_as` to it.
- [ ] Data repo secrets point at the deployer; the platform secret is removed from the data repo.
- [ ] Jobs show **Run as finance-pipeline-runner**; the Bronze and Silver jobs still succeed.
- [ ] Negative tests: the runner cannot change a grant or create a cluster without the policy; the deployer cannot run a job as itself.
- [ ] Existing tables owned by `terraform-platform` stay readable and writable by the runner (grants, not ownership).
- [ ] Control matrix and LLD 2 updated.

## Plan

> **TL;DR:** two-phase, like every IAM change here ([1.3](1.3-least-privilege-deploy-role.md)).

1. Infra PR: create both service principals, grants, role assignment. Apply.
2. Data PR: new secrets, `run_as` → runner. Deploy, run both jobs.
3. Remove the platform secret from the data repo. Run negative tests.

## Out of scope

- Replacing secrets with GitHub OIDC federation (separate item; the platform secret expires ~2026-10-08).
