## Tricky parts

> **TL;DR:** "gated off" is not the same as "invisible".

### 1. Data sources run even when gated
- **Symptom:** the permissions-first apply could not even plan.
- **Cause:** `data "aws_availability_zones"` was not gated. Data sources are **read at plan
  time**, and the role did not yet have the permission to read them.
- **Fix:** give the data source the same `count` as the resources.

### 2. Checkov was blind to gated code
- **Symptom:** clean scans for two days, then 9 failures the moment the flag flipped.
- **Cause:** Checkov evaluates the plan; `count = 0` resources are not in it.
- **Fix:** each of the 9 checked in AWS: all false positives (graph misses `[0]` indexes;
  intra-cluster rules whose source is the SG itself). Documented as skips.
- **Lesson:** a clean scan of code that creates nothing proves nothing.

### 3. State lock collision
- **Cause:** the post-merge CI plan and a manual deploy ran at the same time.
- **Fix:** wait for CI; later both deploy workflows got one shared concurrency group.

### 4. No 3306, no 0.0.0.0/0
- The Databricks docs list 3306 (legacy Hive metastore). We use Unity Catalog, so it stays closed.

## Proof
